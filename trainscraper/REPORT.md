## 5. trainschedule.lk reverse-engineering (how URLs/data were found)

No sitemap coverage for the target routes and no working search form → all URLs were built by
reverse-engineering the site's own encodings (verified against real links on pages):

### 5.1 Station code encoding (base-36, 3 chars)
```
station URL id  =  V(id) where V = id + 123, written in base-36 with digits a-z=0..25, 0-9=26..35
decode(code)    =  a[0] + 36*a[1] + 1296*a[2] - 123        // a[i] = value of char i
```
Verified: `/station/{code}/{slug}-railway-station`. Codes are 3 chars (some old links are 7 chars — 273 were dead).

### 5.2 Route/pair page
```
enc(f) + enc(t) + "a"        // e.g. Colombo Fort -> Kandy
```
98 unique pairs discovered → **212 train types** (`state/traintypes.json`).

### 5.3 Station page
`/station/{code}/{slug}` — lists every train calling there with from/to, arrival, departure, days
(**391 pages, 8,121 rows** → `state/stationpages.json`).

### 5.4 Schedule page
Row links → `/schedule/...` pages with full per-pair timetables
(**2,158 pages, 0 failures** → `state/schedules.json`).

### 5.5 Stops page — the key find
`/stops/{9-char-code}/{from}-to-{to}-train-stops-for-{trainNo}` embeds
**`var stationsData = [...]`** — a JSON array with the *full ordered* stop list, per-stop
arrival/departure, lat/lng, and train model. This became the primary source:
**1,488 stop codes → 1,215 stops pages → 21,769 stop entries** (303 throttled empties recovered by retry).

### 5.6 Known source-side gaps (verified, NOT scraping failures)
- **74 stations have zero schedule data** on trainschedule.lk (Kandy/Up-Country/Matale lines + some halts).
  Their sitemap URLs return "No train schedules found!". → This is exactly what induwara.lk fills.
- 55 trains appear only on station pages (no stops page exists for them).

## 7. Build pipeline — `build.mjs` (single command: `node build.mjs`)

Reads `state/*`, writes all of `out/*`. Stages:

1. **Trains from stops pages** — group `stops.json` entries by trainNo; if a train has several stops
   pages, use the longest (verified to contain the others as subsequence). → **212 trains**.
2. **Trains from station pages only** — trains with no stops page: rows from every station page,
   ordered by *elapsed time since origin departure* (midnight-wrap aware). → **55 trains**.
   - **Variant dedup:** if a train is listed under two `from>to` variants, only the majority variant's
     rows are kept (fixes 1527A, see §9).
   - **Anchor:** departure row taken from the **origin station's own page** (`page.masterName == origin`),
     not any row whose `from` field matches (fixes 7083A, see §9).
3. **Days + type** — union of day tokens across station pages; type from `traintypes.json`
   (55 trains have no type on the source → `"Unknown"`).
4. **Add missing stations** to master (none beyond known ones).
5. **Map source stations → Traventure stationIDs** (see §8).
5.5. **induwara.lk gap trains** appended (see §10).
6. **trainID encoding** (see §11).
7. **Assemble outputs** — `trains-full.json`, `trains-addmultiple.json` (API shape), `trainstops.csv`,
   `stations.*`, `routes.json`.
8. **Write** files + `inserts.sql` (append-only INSERTs; never modifies existing rows).
9. **Report** → `out/report.json`.

## 8. Station mapping to Traventure IDs

Matching order for each of the 391 source stations against Traventure's 188 coastal stations:

1. **exact** normalized name match → 57
2. **fuzzy** Levenshtein on alphanumeric-only key, tolerance `max(1, floor(len*0.25))` → 18 *(all manually verified, see below)*
3. otherwise → **new stationID**, next free ID **189–504** (316 new)

Result: **75 matched (57 exact + 18 fuzzy), 316 new, 13 Traventure stations unmatched**
(lagoons/tunnels/landmarks that have no railway service: Bolgoda Lake, Kalu Ganga, Gin Ganga,
Nakuttiyagama Tunnel, Dedduwawala, … — full list in `out/report.json`).

### 8.1 Fuzzy-pair validation methodology (important if re-run)
A name match is only trusted when **both** hold:
- **coords**: per-station lat/lng averaged from `stops.json` entries fall in the right corridor
  (coastal line ≈ lat 5.9–7.0 / lon 79.8–80.4; main line ≈ lat 7.0–7.4 / lon 80.0–80.4), and
- **sequence bracketing**: in real stop sequences the station sits between the correct neighbours of the
  target Traventure station in its coastal route order (101→188).

All **18 accepted pairs** passed both checks (e.g. `Pategamgoda` nests between Balapitiya#38 and
Ahungalle#36 with coords 6.30,80.04 = Pathagangoda; `Rathgama→Rajgama` sits exactly at coastal idx 54
between Dodanduwa#53 and Boossa#55, coords 6.09,80.14; `Seenigama→Sinigama` at idx 48 between
Hikkaduwa#49 and Telwatte#47, coords 6.16,80.09).

### 8.2 Deny-list — false matches rejected (`build.mjs` → `fuzzyDeny`)
```js
["ragama>rajgama", "kinigama>sinigama", "mirigama>sinigama"]
```
- **Ragama** (7.03,79.92 = Puttalam line) ≠ coastal Rajgama → new station **424**
- **Kinigama** (6.83,81.01 = inland Uva) ≠ coastal Sinigama → new station **313**
- **Mirigama** (7.24,80.13 = main line) ≠ coastal Sinigama → new station

⚠️ **Cascade behaviour:** denying a pair frees the target station for the *next* fuzzy candidate, so after
each deny the fuzzy list must be re-checked (denying Mirigama surfaced `Seenigama→Sinigama`, which was
then validated as **correct**). Current 18 pairs are final and verified.

`out/stations-matchlog.json` holds the full match log; `node validate.mjs` prints it for review.

## 11. Traventure ID encodings

- **trainID = numericPart × 1000 + suffixCode**, suffix codes: `""→0, "SPL"→1, "A"→2, "B"→3`
  (e.g. `1077→1077000`, `1040 SPL→1040001`, `7083A→7083002`). Keeps letter-suffixed numbers unique and
  clear of the existing dummy IDs `1–50, 101`. 278 trainIDs, all unique, 0 collisions.
- **stationID**: existing Traventure 1–188 (coastal) + new **189–504** for source stations not in Traventure.
- **Time format:** `HH:MM:SS` (24 h) everywhere.
- **Days vocabulary** (existing 31 variants): `"Mon, Tue, Wed, Thu, Fri, Sat, Sun, Poya, Holi"` style.
- **Type vocabulary:** `Slow | Express | Semi Express | Intercity Express | Unknown` (varchar 20).
